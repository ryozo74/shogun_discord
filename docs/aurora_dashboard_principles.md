# Aurora ダッシュボード整理原則

> audio2mov 等のプロダクション資料(HTMLダッシュボード)を Aurora で作る際の整理原則。
> 殿御命 2026-06-18 に確立。以後 Aurora 資料はこの原則に従って整理する。

## 1. パイプラインをノードで表す
工程をノード(例 N1物語/N2シーン設計/N3設定/N4ポーズ/N5生成/N6動画)で表し、**各ノードに役職と「何が出るか(成果物)」を明記**する。前処理(例: 音源解析)は独立ノードでなく入力として扱う。

## 2. 各ノードの結果はラベル通りの「実体」を持つ
ノードの結果域には**実際の成果物**(台本/演出/設定画/骨格/実画像)を表示する。サマリー文・「○○を参照」だけで終わらせない。**空・サマリーのみは不可**。再編で番号を変えたら**中身も追随**させる(ラベルだけ変えて中身が1ノードずれる事故を防ぐ)。

## 3. 暗テーマで統一
**白/明背景禁止**(#f5f6fa / #eef0ff / #fff / white)。暗い半透明背景(rgba(255,255,255,.04〜.06)等)+淡色文字(#eef0f7/#c8cdd8)。読みやすいコントラストは維持。明背景上の暗文字(#111/#222/#333)も排す。

## 4. 「何を示すか」を明示
分析ブロック(モチーフ反復/連続性5問 等)は、見出し直下に**「何の設計か・どう読むか」の1-2文イントロ**を必ず付す。データの羅列に意味の枠を与える(中身が在っても説明が無いと伝わらない)。

## 5. 色でセグメンテーション
**ノード固有色 = 結果見出し色 = 結果カード色(三位一体)**。色を見ればどのノードの成果物か分かる。ステータス(完了/進行中/待機)は色でなくバッジ(✅🔄⏳)/枠線で別表現する。

## 6. セクション開閉
各主要見出しをクリックで開閉(collapse/expand)。**既定は全開**(読込時は全部見える)。長い資料を畳んで見やすく。

## 7. ノードクリック→成果物へスクロール
フローチャートのノードを押すと、対応する結果域へ `scrollIntoView({behavior:'smooth'})`。フローチャートを目次/ナビとして機能させる。閉じたセクションへ飛ぶ時は開いてからスクロール。

## 8. 画像比較は「手法ごとに最新1枚」
生成テスト結果は**生成モデル・手法(Flux/Anima/SD+ControlNet/Ideogram)ごとに最新1枚**を並べ比較する。固定ファイル名・上書き方式で版を増やさず最新のみ保持。被写体でなく手法が比較軸。

## 9. 役割の分離(重複させぬ)
N1物語=「何が起きるか(台本)」/ N2演出=「どう撮る・見せるか」/ N3設定=「設定イメージ」。各ノードは自分の層に徹し、内容を重複させない。

## 10. QC: ラベル↔中身の一致を必ず検査
品質チェックは「○○が無い」だけでなく **「○○が在る・各ノードがラベル通りの実体を持つ」を必ず確認**する。空 / サマリーのみ / 中身ずれ / 白背景残存 / 説明欠如 は FAIL とする。

---
*この原則は、混乱(ノードずれ・空ノード・白背景・意味不明ブロック)を一掃した 2026-06-18 の総点検で確立された。Aurora 資料の整理はこれを正とする。*
